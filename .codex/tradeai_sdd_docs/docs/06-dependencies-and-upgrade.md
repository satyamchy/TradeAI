# 06 — Dependencies and Upgrade Specification

## 1. Current state

The current TradeAI `backend/requirements.txt` on the repository main branch contains, among other dependencies:

```text
langgraph>=0.6.0
langchain-core>=0.3.70
langchain-groq>=0.3.7
```

It also uses FastAPI, Pydantic 2, SQLAlchemy, `aiosqlite`, `asyncpg`, `yfinance`, NumPy and `dhanhq`.

## 2. TradingAgents v0.7.1 dependency requirements

The tagged `v0.7.1` `pyproject.toml` declares:

- Python `>=3.11`.
- `langchain-core>=1.6.5`.
- `langgraph>=1.2.12`.
- `langgraph-checkpoint-sqlite>=3.1.1`.
- `pandas>=3.0.6`.
- `yfinance>=1.7.0`.
- Provider packages including `langchain-openai`, `langchain-anthropic` and `langchain-google-genai`.

This means upgrading TradeAI's LangGraph/Core dependencies is required for a same-environment, single-app integration. Existing TradeAI LangGraph code must be compatibility-tested and may require API migration.

## 3. Latest versions checked on 31 October 2026

| Package | Latest/version checked | Decision |
|---|---:|---|
| `langgraph` | `1.2.19` (PyPI upload 30 Oct 2026) | Candidate exact pin after integration tests |
| `langchain-core` | `1.7.3` (PyPI upload 29 Oct 2026) | Candidate exact pin after integration tests |
| `tradingagents` | GitHub release `v0.7.1` (27 Oct 2026) | Pin release tag; do not use moving `main` |
| `langchain-groq` | `1.1.3` (latest PyPI version observed) | Upgrade existing provider integration and test Groq model calls |

Do not confuse the latest released versions with compatibility proof. The actual resolved environment must pass `pip check`, imports, provider smoke tests, existing application tests and end-to-end tests.

## 4. Upgrade policy

1. Create an upgrade branch before changing requirements.
2. Create a clean virtual environment using Python 3.11 or later. Start with the currently used Python minor version if it is at least 3.11; do not change Python and framework versions simultaneously unless necessary.
3. Install the pinned TradingAgents v0.7.1 release/tag and its declared dependencies.
4. Set LangGraph/Core candidate versions to the checked versions above, then resolve the whole environment.
5. Upgrade `langchain-groq` to a release compatible with LangChain Core 1.x.
6. Review all other dependency conflicts; do not resolve them with `--no-deps` or by silently downgrading TradingAgents requirements.
7. Run `python -m pip check`.
8. Run tests for the existing TradeAI conversation graph, technical tools, stock analysis, Dhan service and harness.
9. Run a TradingAgents smoke test on one NSE ticker (for example `RELIANCE.NS`) using a supported LLM provider.
10. Commit a resolved lock file only after all gates pass.

## 5. Installation approach

Use the tagged release, not `main`. Example installation source:

```text
tradingagents @ git+https://github.com/TauricResearch/TradingAgents.git@v0.7.1
```

Candidate pins for the two core packages:

```text
langgraph==1.2.19
langchain-core==1.7.3
```

The exact final requirements/lock file must be generated by the resolver and tests. This document is not intended to be copied as a complete requirements file: TradingAgents brings additional dependencies and the complete app has other provider, database and broker packages.

## 6. API compatibility migration checklist

Review the existing LangGraph/LangChain code for:

- Imports moved or removed in LangChain 1.x / LangGraph 1.x.
- Model/provider constructor changes.
- Prompt, message and structured-output interfaces.
- Tool invocation and tool result types.
- Graph compile/invoke/stream methods and config/checkpoint types.
- Pydantic v2 model behavior.
- Exception types and retry semantics.
- Any use of private/internal package APIs.

Do not rewrite working graphs wholesale. Upgrade one existing AI workflow, run its tests, then move to the next. Keep user-facing chat behavior stable.

## 7. TradingAgents integration constraints

The v0.7.1 public README documents `TradingAgentsGraph`, `DEFAULT_CONFIG`, `.propagate(ticker, date)` and optional `PortfolioContext`. It documents Indian ticker syntax such as `RELIANCE.NS`.

- Use documented public imports and calls.
- Do not patch the library's source.
- Keep provider config in TradeAI settings and environment variables.
- Preserve the raw upstream rating and normalize it in TradeAI's mapper.
- Configure TradingAgents' documented memory/checkpoint paths separately from the TradeAI application database.
- Validate the actual v0.7.1 package at runtime; do not assume internal state field names based on older tutorials.
- TradingAgents describes itself as a research framework; its own Portfolio Manager uses a simulated exchange. TradeAI's Dhan execution remains separate.

## 8. Upgrade acceptance criteria

- Clean environment install succeeds from the committed dependency lock.
- `pip check` reports no broken requirements.
- Existing TradeAI AI workflows pass regression tests.
- TradingAgents can analyze a supported Indian ticker and return a decision/state.
- FastAPI starts and serves health endpoints.
- No existing Dhan/harness tests regress due to framework upgrade.


## 9. TradingAgents feature configuration requirements

Module 2 may configure these supported features through the pinned package API/config; verify names against the installed version before use:

- Analyst selection and parallel analyst workflow.
- Quick/deep model IDs and, where supported, a distinct provider/backend URL for each tier.
- Debate and risk round limits.
- `PortfolioContext` as an optional argument to `propagate()`.
- Report persistence, including `complete_report.html` where supported by the release.
- Decision-memory path via `TRADINGAGENTS_MEMORY_LOG_PATH` (the current README describes the memory log as always on).
- Checkpoint/resume via the supported `checkpoint_enabled` setting and `TRADINGAGENTS_CACHE_DIR`; keep opt-in until recovery tests pass.
- Optional Jev/TypeSafe filtering of Reddit and StockTwits sentiment posts when separately configured.
- Upstream `run_backtest` APIs for research-rating evaluation, with a separate TradeAI simulator for actual strategy/fees/slippage.

Do not persist the complete upstream `DEFAULT_CONFIG` blindly if it contains secrets or non-serializable values. Persist a sanitized configuration snapshot containing profile version, provider/model names, analyst selection, round limits and relevant feature flags. Secrets remain in environment variables.

## 10. Upgrade workflow: structure before integration

The first structural refactor should not combine file moves, dependency major-version upgrades and TradingAgents integration in one change. Use this order:

1. Capture a passing/failing baseline on the current dependency set.
2. Create module folders, contracts and test directories without changing runtime dependencies.
3. Confirm the app starts and legacy regression tests still pass.
4. Create a dedicated dependency-upgrade branch/change.
5. Update LangGraph/LangChain Core and related provider integrations to a compatible pinned set.
6. Run `pip check`, existing LangGraph/chat/analysis tests and Dhan/harness regression tests.
7. Install/import TradingAgents v0.7.1 and run a mocked adapter test.
8. Run one controlled external smoke test for an NSE ticker with a configured provider.
9. Commit the lock file only after every gate passes.
